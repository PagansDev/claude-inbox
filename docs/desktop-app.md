# Desktop app (Tauri)

## Layout

| Path | What it holds |
|------|---------------|
| `index.html`, `src/` | React frontend, built by Vite into `dist/` |
| `src-tauri/` | Rust crate `claude-inbox` (library `claude_inbox_lib`) and the Tauri config |
| `src-tauri/tauri.conf.json` | Window, identifier, build commands, CSP |
| `src-tauri/capabilities/default.json` | Permissions granted to the `main` window |

Module folders from ADR 04 (`server/`, `queue/`, `hooks/`, `installer/`, `components/`, `features/`, `i18n/`) are created when their first code lands.

## Running

| Command | What it does |
|---------|--------------|
| `npm run tauri dev` | Starts Vite on port 1420 and opens the app with hot reload |
| `npm run tauri build -- --no-bundle` | Builds the release binary at `src-tauri/target/release/claude-inbox` |
| `npm run dev` | Vite only, in a browser, without Tauri APIs |

On Linux, the system needs `libwebkit2gtk-4.1-dev`, `libsoup-3.0-dev`, `libjavascriptcoregtk-4.1-dev` and `librsvg2-dev`. The Rust toolchain needs the `rustfmt` and `clippy` components (`rustup component add rustfmt clippy`).

## Decisions that would otherwise be comments

- **`windows_subsystem` in `src-tauri/src/main.rs`:** `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` stops Windows release builds from opening a console window next to the app. Do not remove it. It has no effect on Linux or macOS.
- **`main.rs` and `lib.rs` split:** `main.rs` only calls `claude_inbox_lib::run()`. The app lives in the library so the same code can be tested and reused by mobile entry points (`mobile_entry_point`), as generated by `tauri init`.
- **Identifier `dev.pagans.claude-inbox`:** reverse-domain form required by Tauri. It names the app's config and data directories (for example `~/.config/dev.pagans.claude-inbox/` on Linux), where the MVP keeps the hook token (ADR 03).
- **Content Security Policy:** `default-src 'self'; connect-src ipc: http://ipc.localhost; img-src 'self' data:`. The webview loads only bundled assets and talks only to the Tauri IPC channel. At build time, Tauri adds hashes and nonces for the app's own scripts and styles. External fonts or images would need an explicit change here.
- **Dependencies removed from the `tauri init` output:** `serde`, `serde_json`, `log` and `tauri-plugin-log` were dropped because nothing uses them yet (YAGNI). The MVP adds what the hook server needs.
- **Vite config:** follows the Tauri guide.
  - Fixed port 1420 with `strictPort`, so `tauri dev` fails instead of loading the wrong URL.
  - `src-tauri` is ignored by the watcher.
  - `envPrefix` exposes `VITE_` and `TAURI_ENV_*`.
  - The build targets `safari13` (WebKit) on Linux and macOS, and `chrome105` on Windows.

## Frontend conventions

- Colours and fonts are Tailwind theme tokens in `src/index.css` (`canvas`, `surface`, `ink`, `muted`, `accent`). Components use the tokens, not raw colours.
- Icons come from `lucide-react`, never emoji. Decorative icons carry `aria-hidden="true"`.
- No external fonts: the CSP allows only bundled assets. The font stacks fall back to the system fonts.
